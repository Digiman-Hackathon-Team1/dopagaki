# [ADR-0014] 안전 정지·답변 금액 검증·실패 시 시세표 안내

* **상태 (Status):** 채택됨(Accepted)
* **날짜 (Date):** 2026-11-27
* **관련 (Related):** T6 #9, ADR 0003·0005·0009, 설계 문서 4.8·6장·8장·12장·FR-06·FR-07·FR-08(v1.4)

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:** 데모 중에 위험한 추천이나 틀린 금액이 나가면 안 되고, LLM이 실패해도 화면이 멈추면 안 된다(이슈 #9). 설계는 세 가지를 정했다.
  * 안전 정지: 키워드로 임신·수유·질환·복용약 언급을 표시하고, 멈출지는 LLM이 문맥으로 판단한다(12장).
  * 숫자 검증: 응답 전에 답변 속 금액을 도구 결과와 대조한다(6장, 12장).
  * 대체 동작: LLM 오류·시간 초과·한도 초과 시 시세표로 안내한다(FR-08).
* **문제:**
  * 안전 정지를 누가 최종 판단하는지, 판단 결과를 화면에 어떻게 내보내는지(FR-07 카드 목록의 "안전" 카드와 4.8 "건강 정보는 화면에 넣지 않는다")가 정해지지 않았다.
  * 금액이 틀렸을 때 고칠지, 지울지, 다시 물을지가 정해지지 않았다. 실제로 Haiku는 "約¥21,000以上安くなります"(약 2만 1천 엔 이상 싸요)처럼 반올림했고, "1万ウォン＝約¥11.8"(1만 원은 약 11.8엔)처럼 환율을 틀리게 직접 계산했다. Sonnet은 두 시술의 합계(¥111,320)를 직접 더했다.
  * 실패 응답의 HTTP 상태와 형식이 정해지지 않았다. 기존에는 키가 없으면 503, LLM 오류는 500이었다.
* **목표:** 같은 입력에는 같은 방식으로 거르고, LLM이 틀려도 코드가 막으며, 실패해도 다음 턴을 이어 갈 수 있게 한다.

## 2. 고려한 옵션들 (Considered Options)

### 안전 정지 판단

#### 1. 키워드는 표시만, 멈춤은 LLM이 응답 칸(`safety_stop`)으로 정하고 코드가 카드를 뺀다

`safety_check` 노드가 대화의 사용자 메시지에서 키워드를 찾으면 그 턴 사용자 메시지 끝에 안내 블록을 붙인다. Claude는 응답 칸 `safety_stop`을 true로 하고 답변에 이유 한 줄, 병원에 확인할 것, 나중에 다시 찾아 주겠다는 말을 쓴다. finalize는 `safety_stop`이면 카드와 제외 사유를 모두 뺀다.

**Pros**
* "임신 계획은 없어요"처럼 부정하는 말을 문맥으로 가른다(FR-06 완료 기준).
* LLM이 검색을 해 버려도 카드가 나가지 않는다.
* 앞 턴에 말한 건강 정보도 매 턴 다시 표시하므로 다음 턴에 정지가 유지된다.

**Cons**
* 멈출지 자체는 LLM 판단이라 놓칠 수 있다. 실제 테스트 시나리오로 확인한다.

#### 2. 키워드가 나오면 코드가 바로 멈춤

**Pros**
* 놓치지 않는다.

**Cons**
* 부정 표현, 수유역(서울 지하철역) 같은 말에도 멈춘다. FR-06 완료 기준을 못 맞춘다.

#### 3. 별도 LLM 판정 호출

**Pros**
* 판정만 하는 프롬프트라 정확할 수 있다.

**Cons**
* 턴마다 LLM 호출이 하나 늘어난다. 설계 8장은 safety_check를 LLM 없는 노드로 정했다.

### 답변 금액이 도구 결과와 다를 때

#### 1. 그 금액이 든 부분을 지운다

통화 표시(¥, 円, 엔, ₩, 원, ウォン)가 붙은 숫자만 금액으로 본다. 이 대화의 도구 결과(카드 데이터의 `_jpy`·`_krw` 필드와 결과 문장)와 사용자 메시지(예산 등)에 같은 값이 없으면, 그 금액이 든 괄호를 지우고, 괄호 밖이면 문장을, 표·목록이면 그 줄을 지운다. 지웠으면 주의사항에 "금액은 카드에서 확인해 달라"는 한 줄을 붙인다.

**Pros**
* 추가 LLM 호출이 없다. 결과가 항상 같다.
* 카드 금액은 도구 결과 그대로라 사용자는 카드에서 맞는 금액을 본다.

**Cons**
* 금액이 아닌 정보도 같은 문장에 있으면 함께 지워진다.
* 정확히 같은 값만 통과한다. 반올림한 금액, 합계, LLM이 직접 한 환산은 모두 지워진다(의도한 동작).

#### 2. 맞는 금액으로 바꿔 쓴다

**Cons**
* "약 2만 엔"이 어느 카드의 어느 금액인지 코드가 알 수 없다.

#### 3. LLM에 다시 쓰게 한다

**Cons**
* LLM 호출이 늘고, 사용자가 쓰지 않은 사용자 메시지를 대화 기록에 넣어야 한다(대화 중간 시스템 메시지는 쓰지 않음, graph.py 머리말).

### 실패 응답

#### 1. 200 응답에 시세표 안내와 `fallback` 칸

`ChatResponse.fallback`이 `error`(키 없음·LLM 오류·시간 초과·빈 응답 두 번·형식 오류·단계 한도) 또는 `daily_limit`(사용자별·전체 하루 한도)이고, 답변에 시세표 안내 문장을 넣는다. 정상 답변이면 null이다.

**Pros**
* 화면은 같은 응답 형식으로 그리고, `fallback`을 보고 시세표로 가는 길을 붙일 수 있다.
* 오류 난 호출과 빈 응답은 대화 기록에 넣지 않으므로 다음 턴이 정상 요청이 된다. 형식이 틀린 응답은 글이 있어 기록에 남아도 다음 턴 요청은 유효하다.

**Cons**
* HTTP 상태로는 실패를 구분하지 못한다. 화면은 `fallback`을 봐야 한다.

#### 2. 오류 상태 코드(503, 429)와 오류 본문

**Cons**
* FR-08 완료 기준(오류 대신 시세표 안내)과 맞지 않는다.

## 3. 결정 사항 (Decision Outcome)

* **안전 정지는 옵션 1(키워드 표시 + LLM `safety_stop` + 코드가 카드 제거)을 선택한다.** 안전 카드는 만들지 않는다(설계 v1.4에서 FR-07의 "안전" 카드를 뺐다). `safety_stop`은 응답에 내보내지 않는다(설계 4.8, `apps/api/AGENTS.md`).
  * 멈춘 턴의 답변은 결론과 이유(한두 문장) → 이번 여행에서 할 일(병원에 알리기, 담당 의사에게 묻기, 진정·보습 위주 관리) → "준비되면 다시 찾아드릴게요" 순서로 쓴다. 이유 한 줄만으로는 다음에 할 일을 알 수 없어서다.
  * 병원·대응 카드와 제외 사유는 빼고, 기준 위치 카드는 남긴다. 위치는 건강 정보가 아니고 다시 찾을 때 쓴다.
  * 조건 요약·주의사항·카드 이유에서는 같은 키워드로 건강 정보를 거른다. 다음 질문 제안은 멈추지 않은 턴에만 거른다. 멈춘 턴의 제안("임신 중에도 받을 수 있는 관리는?")은 사용자가 이어 물을 문장이라 남긴다.
  * 정보 확인차 물었다고 하는 등 해당하지 않는다고 밝히면 Claude가 정지를 풀고 이어서 추천한다(실제 테스트로 확인).
* **금액은 옵션 1(지우기)을 선택한다.** 검사 대상은 답변·조건 요약·주의사항·카드 이유다. 질문 선택지와 다음 질문 제안은 사용자가 보낼 문장이라 검사하지 않는다. 시스템 프롬프트에도 "금액을 그대로 옮기고, 반올림·합산·환산하지 않는다"를 넣었다.
* **실패는 옵션 1(200 + `fallback`)을 선택한다.**
* 실행 한도 기본값: 한 턴 LLM 호출 10번(실제 Sonnet이 7번 만에 끝낸 턴이 있었고 8번에서 잘린 턴이 있었다), 한 턴 전체 180초(넘으면 다음 LLM 호출을 하지 않음. 이미 시작한 호출은 기다리므로 최악은 180초 + 호출 하나), LLM 호출 하나 60초와 재시도 2번, 하루(UTC) 대화 요청 전체 500번과 사용자별 50번(설계 8장의 한 대화 최대 턴 수와 같음). 모두 환경변수로 바꾼다. 기존 Worker의 500은 하루 모델 호출 수이고 여기는 대화 요청 수라, 같은 500이어도 LLM 호출은 더 많다.
* 빈 응답은 턴마다 한 번 다시 요청하고, 그 재요청도 단계 한도에 센다. 도구 호출도 글도 없거나, 응답 칸 형식이지만 답변·질문·카드 이유가 모두 비면 빈 응답이다(Haiku가 모든 칸이 빈 응답을 돌려준 적이 있다).
* 건강 정보 키워드는 데이터의 병원·역·지역·시술 이름에 걸리지 않게 좁힌다. "수유"는 역·동네·병원 지점(미앤미의원 수유점) 이름이라 "수유 중"처럼 쓸 때만 찾는다. 테스트가 데이터 이름 전체를 검사한다.

**이유**
* 금액과 안전처럼 매번 같아야 하는 것은 코드가 막는다는 원칙(ADR 0005)과 맞다.
* 실패 처리에서 답 없는 assistant 메시지를 기록에 남기지 않아야 다음 턴이 400 오류가 되지 않는다(ADR 0006, graph.py 머리말).

**후속 작업**
* web: `fallback`이 있으면 시세표로 가는 버튼을 붙인다(화면 담당과 맞춤).
* 하루 한도는 서버 메모리에 세므로 재시작하면 0부터 센다. 사용자 ID는 익명이라 바꿔 보내면 사용자별 한도를 피한다. 비용 상한은 전체 한도가 맡는다. 배포 저장소가 정해지면 옮긴다.
