# [ADR-0002] 버튼식 상담을 에이전트로 대체하고, 실패 시 시세표로 안내

* **상태 (Status):** 채택됨(Accepted). 황인식 님 동의(2026-11-27, 슬랙)
* **날짜 (Date):** 2026-11-26
* **관련 (Related):** T0 #3, #43, #45, #44

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:** web에는 버튼식 추천 상담("AI 상담실장 도파" 탭)이 있다. 칩과 규칙으로 조건을 받고, 규칙이 못 알아들은 문장만 Cloudflare Worker(`apps/worker`)가 Claude로 조건을 뽑아 돌려준다. 에이전트는 같은 일을 대화로 하고, 추천·일본 시술명·예약 연결까지 맡는다.
* **문제:** 버튼식 상담과 에이전트를 둘 다 두면 같은 기능이 두 벌이 된다. 에이전트가 실패했을 때 사용자가 어디로 가야 하는지도 정해야 한다.
* **목표:** 상담 기능을 하나로 정하고, 에이전트가 실패해도 사용자가 가격 정보를 볼 수 있게 한다.

## 2. 고려한 옵션들 (Considered Options)

### 1. 에이전트가 버튼식 상담을 대체 (하위호환 없음)

버튼식 상담을 에이전트로 바꾼다. 에이전트 실패(LLM 오류, 시간 초과, 한도 초과) 시 시세표로 안내한다.

**Pros**
* 상담 기능이 하나라 유지할 코드가 줄어든다.
* 실패 시 안내 대상인 시세표는 LLM 없이 동작한다.

**Cons**
* 기존 Worker는 쓰임이 없어진다(정리 필요).
* web 화면 수정이 필요하다(프론트 담당 영역).

### 2. 버튼식 상담과 병행

버튼식 상담을 남기고 에이전트를 추가한다. 에이전트 실패 시 버튼식 상담으로 돌아간다.

**Pros**
* 기존 화면을 바꾸지 않아도 된다.

**Cons**
* 같은 기능을 두 벌 유지한다.
* 버튼식 상담의 문장 해석도 Worker를 거쳐 Claude를 부르므로, Claude 장애 때는 Worker도 함께 실패하고 규칙 기반 해석만 남는다(`apps/web/src/lib/concierge-ai.ts`).

## 3. 결정 사항 (Decision Outcome)

* **에이전트가 버튼식 상담을 대체하고, 실패 시 시세표로 안내한다.**
* **버튼식 상담과 병행하는 방식은 채택하지 않는다.**

**이유**
* 같은 기능을 두 벌 유지할 이유가 없다.
* 실패 시 대체 경로는 LLM에 의존하지 않아야 한다. 시세표는 LLM 없이 동작하지만, 버튼식 상담의 문장 해석(Worker)은 Claude에 의존한다.
* 설계 문서 1장(버튼식 상담 대체)과 2장 대체 동작, FR-08과 맞는다.

**적용 (#44)**
* AI 상담 탭은 에이전트 대화(`apps/web/src/components/AgentConsultView.tsx`)만 둔다. 버튼식 단계와 규칙 기반 결과, 문장 해석(`concierge-parse.ts`, `concierge-ai.ts`), Worker(`apps/worker`), `VITE_CONCIERGE_API`는 지웠다.
* 버튼식 상담에만 있던 묶음 추천(#43, ADR 0016)과 일정 플랜(#45, ADR 0017)은 그 전에 에이전트 도구로 옮겼다.
* 에이전트가 실패 응답(`fallback`)을 주거나 응답이 없으면(연결 실패·서버 오류) 시세표 안내를 보여 준다.
* 회복 기간·바늘 여부·고민별 시술표는 `apps/web/src/lib/treatment-rules.ts`로 옮겼다. 에이전트 데이터 스냅샷(ADR 0001)의 원본이다.
* 홈 구성 확인은 설계 문서 15장에 남아 있다(황인식·손창현 님).
