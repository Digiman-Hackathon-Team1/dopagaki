# [ADR-0020] 응답 언어는 코드가 글자로 1차 판별하고 Claude가 뜻으로 최종 결정하며, 서버 문구는 실제 답의 언어를 따른다

* **상태 (Status):** 채택됨(Accepted)
* **날짜 (Date):** 2026-11-29
* **관련 (Related):** #76, #68(프롬프트 캐싱), ADR 0015, 설계 문서 2장 응답 언어·8장 그래프·10장 API

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:** 응답 언어가 화면 언어(요청의 `lang`)로 정해졌다. 일본어 화면에서 "리쥬란 얼마예요?"라고 물어도 답변·다음 질문 제안·면책 문구가 일본어로 나왔다.
* **문제:**
  * 서버가 붙이는 문구(면책, 금액 주의, 시세표 안내 4종)도 언어를 알아야 한다. 이 중 처리 중(`busy`)·턴 상한·하루 한도·키 없음 안내와 데모 녹화본 찾기는 Claude를 부르기 전에 정해야 한다.
  * 메시지 글자 수만으로는 뜻을 모른다. 예를 들어 "한국어로 말해줘. リジュランの価格"(한글 7자, 일본어 8자)는 일본어로, "밴스의원 홍대점 どう?"(한국어 병원 이름 + 일본어 질문)는 한국어로 판정된다. 팀원(황인식)이 이런 경우를 짚었다.
  * 언어 안내를 시스템 프롬프트에 넣으면 프롬프트 캐시(#68)가 갈라지고, 이전 턴 thinking 블록이 거부될 수 있다.
* **목표:** 사용자가 그 턴에 쓴 언어로 답하고, 서버 문구도 같은 언어로 붙인다. 추가 LLM 호출은 없어야 하고, 캐시도 유지돼야 한다.

## 2. 고려한 옵션들 (Considered Options)

* **프롬프트에만 지시("사용자가 쓴 언어로 답해")**: 답은 맞출 수 있다. 하지만 코드가 언어를 모르니 면책 문구·시세표 안내를 고를 수 없다.
* **판별용 LLM 호출**: 뜻까지 본다. 대신 턴마다 호출이 하나 늘어 비용·지연이 커지고, Claude를 부르지 않는 안내에는 쓸 수 없다.
* **코드 글자 수만(설계 v1.12)**: 결과가 늘 같아 단위 테스트로 모두 확인할 수 있다. 하지만 위 두 예처럼 명시 요청과 고유명사가 섞인 문장을 틀린다. 규칙을 더하면 다른 쪽에서 새 오판이 생긴다(예: 가타카나 예외를 넣으면 "강남 リジュラン"이 한국어가 된다).
* **하이브리드, 응답 칸 `reply_lang` 추가(팀원 제안)**: Claude가 고른 언어를 칸에 적게 한다. 하지만 칸과 실제로 쓴 답의 언어가 다를 수 있다. 응답 스키마·가짜 LLM·녹화본도 바꿔야 한다.
* **하이브리드, 실제 답 글자로 확인(채택)**: Claude가 뜻으로 언어를 고른다. 코드는 Claude가 실제로 쓴 답의 글자를 다시 세어 서버 문구 언어를 정한다. 응답 스키마는 그대로다.

## 3. 결정 사항 (Decision Outcome)

* **선택한 옵션:** 하이브리드, 실제 답 글자로 확인.
  * **1차 판별(코드, `api/agent/lang.py`):**
    * 메시지의 한글 수와 일본어 글자 수(히라가나 + 가타카나 + 한자)를 세어 많은 쪽으로 정한다.
    * 한글이 있고 일본어 글자가 가타카나뿐이면 한국어로 본다("リジュラン 얼마?").
    * 같거나 둘 다 0이면 직전 턴 응답 언어, 첫 턴이면 화면 언어를 쓴다.
    * 이 값을 쓰는 곳: 턴 상한·하루 한도·키 없음·오류 안내, 데모 녹화본 찾기, Claude에게 건네는 "모호할 때 쓸 언어".
    * `busy` 안내는 대화 잠금 전이라 대화 기록을 읽지 않는다. 그래서 이번 메시지 글자만 보고, 못 정하면 화면 언어를 쓴다.
  * **최종 언어(Claude):**
    * 언어 안내는 지금처럼 그 턴 사용자 메시지 끝에 붙인다.
    * 문장은 이렇다: "사용자 자신의 문장이 쓰인 언어로 답하라. 이름이 아니라 조사·어미·의문사로 판단한다. 한국어 문장 속 일본 시술명은 한국어이고, 일본어 문장 속 한국 병원·장소 이름은 일본어다(예시 한 개씩). 화면 언어와 사용자가 일본인이라는 점으로 정하지 않는다. 언어를 요청하면 그 언어로. 메시지로 알 수 없으면(이름·숫자·영어만) 1차 판별 언어로."
    * 시스템 프롬프트는 "모든 칸을 그 한 언어로 쓴다"로만 바꾼다. 턴마다 같으므로 캐시 앞부분은 바뀌지 않는다.
  * **확인(코드, finalize):**
    * Claude가 쓴 답변·조건 요약·질문·다음 질문 제안의 글자를 세어 이번 응답 언어로 정한다. 정할 수 없으면 1차 판별을 쓴다.
    * 이 언어로 면책·금액 주의 문구를 붙인다.
    * 응답 `ChatResponse.lang`에 담고, 대화 상태에 남겨 다음 턴의 직전 턴 언어로 쓴다.
* **선택 이유:**
  * 언어를 맞히는 데는 문장의 뜻이 필요하다. 한편 서버 문구는 사용자가 실제로 보는 답과 같은 언어여야 한다.
  * Claude가 고르고 코드가 답 글자로 확인하면 두 조건을 모두 채운다. 추가 호출도 없다.
  * 1차 판별은 글자 수 방식 그대로라, 측정 결과가 나쁘면 언어 안내만 바꿔 코드 판별로 되돌릴 수 있다(`scripts/eval_reply_lang.py --mode code`가 그 비교다).

## 4. 측정 (실제 Claude, Haiku)

`scripts/eval_reply_lang.py`로 혼합 입력 16개(판단이 갈릴 수 있는 1개 포함)를 돌렸다.

| 방법 | 맞힘(회) | 3회 모두 맞힌 케이스 | 칸 사이 언어 섞임 |
|---|---|---|---|
| 코드가 언어 지정(`--mode code`, 1회) | 11/15 | 11/15 | 0 |
| Claude가 판단, 첫 언어 안내 | 40/45 | 12/15 | 1 |
| Claude가 판단, 보강한 언어 안내(채택) | **45/45** | **15/15** | 1 |

* 판단이 갈릴 수 있는 1개("강남 リジュラン")는 위 숫자에서 뺐다. 세 방식 모두 한국어로 답했고, 채택안에서는 1회 칸 사이 언어가 섞였다(위 섞임 1건).
* 코드 지정이 틀린 4개: 명시 요청 3개("한국어로 말해줘. リジュランの価格", "韓国語で答えて。…", "일본어로 알려줘. 리쥬란 가격")와 한국 병원 이름이 긴 일본어 문장("밴스의원 홍대점 どう?"). Claude 판단은 두 안내 모두 이 4개를 3회 다 맞혔다.
* 첫 안내("다른 언어로 쓴 이름으로 정하지 말라")에서는 일본어 화면에서 일본 시술명이 섞인 한국어 질문을 일본어로 답했다. "リジュラン 얼마?" 1/3, "リジュランアイ 얼마예요?" 2/3, "일본에서 ハイフ 받았는데 서울에서 얼마예요?" 2/3이 틀렸다. 시스템 프롬프트가 일본인 사용자 상담원으로 시작하고 화면도 일본어라 일본어 쪽으로 기운 것으로 본다(추정).
* 그래서 안내에 세 가지를 더했다. 이름이 아니라 조사·어미로 판단하라는 것, 한국어 문장 속 일본 시술명과 일본어 문장 속 한국 병원 이름 예시, 화면 언어와 사용자가 일본인이라는 점으로 정하지 말라는 것이다. 예시는 측정 입력과 다른 문장으로 두었다.
* 측정 한계: 케이스가 16개라 작다. 모델은 Haiku 5.5만 썼다.

## 5. 결과 및 영향 (Consequences)

* **장점:**
  * 명시 요청과 고유명사가 섞인 문장도 뜻으로 맞힌다(4절, 코드 지정 11/15 → 15/15).
  * 면책·금액 주의 문구는 항상 화면에 나간 답과 같은 언어다.
  * 1차 판별은 결정적이라 시세표 안내·데모 녹화본 찾기는 단위 테스트로 확인한다.
* **단점 및 위험:**
  * 최종 언어는 확률적이다. 같은 입력도 실행마다 다를 수 있어, 실제 Claude 측정(4절)으로만 확인한다.
  * Claude를 부르지 않는 안내는 1차 판별을 쓴다. 그래서 같은 메시지라도 정상 답과 오류 안내의 언어가 다를 수 있다. 예: "한국어로 말해줘. リジュランの価格"는 정상 답은 한국어, 오류 안내는 일본어다.
  * 화면 언어 전환 버튼은 이제 다음 답의 언어를 바꾸지 않는다. 답은 사용자가 쓴 언어를 따른다.
  * web이 만드는 글자는 화면 언어다. "이어서 물어보기" 같은 제목, 시세표 보기 상자, 카드 예약 버튼이 보내는 문장이 여기에 해당한다. 그중 카드 버튼 문장은 다음 턴 입력이 되므로, 화면 언어로 보내면 대화 언어가 바뀐다. 응답의 `lang`으로 맞추는 일은 web 담당과 이어서 한다.
  * 데모 대본은 이 변경 뒤에 녹화한다. `record_demo.py`는 1차 판별이나 답 언어가 `--lang`과 다르면 녹화하지 않는다.
