# [ADR-0020] 응답 언어는 코드가 글자로 정하고, 사용자가 언어를 직접 요청할 때만 Claude가 바꾸며, 서버 문구는 실제 답의 언어를 따른다

* **상태 (Status):** 채택됨(Accepted)
* **날짜 (Date):** 2026-11-29
* **관련 (Related):** #76, #68(프롬프트 캐싱), ADR 0015, 설계 문서 2장 응답 언어·8장 그래프·10장 API

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:** 응답 언어가 화면 언어(요청의 `lang`)로 정해졌다. 일본어 화면에서 "리쥬란 얼마예요?"라고 물어도 답변·다음 질문 제안·면책 문구가 일본어로 나왔다.
* **문제:**
  * 서버가 붙이는 문구(면책, 금액 주의, 시세표 안내 4종)도 언어를 알아야 한다. 처리 중(`busy`)·턴 상한·하루 한도·키 없음 안내와 데모 녹화본 찾기는 Claude를 부르기 전에 정해야 한다.
  * 메시지 글자 수만으로는 뜻을 모른다. "한국어로 말해줘. リジュランの価格"(한글 7자, 일본어 8자)는 일본어로, "밴스의원 홍대점 どう?"(한국 병원 이름 + 일본어 질문)는 한국어로 판정된다. 팀원(황인식)이 이런 경우를 짚었다.
  * 언어 안내를 시스템 프롬프트에 넣으면 프롬프트 캐시(#68)가 갈라지고, 이전 턴 thinking 블록이 거부될 수 있다.
* **목표:** 사용자가 그 턴에 쓴 언어로 답하고, 서버 문구도 같은 언어로 붙인다. 추가 LLM 호출 없이, 캐시를 유지한다.

## 2. 고려한 옵션들 (Considered Options)

* **프롬프트에만 지시("사용자가 쓴 언어로 답해")**: 코드가 언어를 모르니 면책 문구·시세표 안내를 고를 수 없다.
* **판별용 LLM 호출**: 턴마다 호출이 하나 늘어 비용·지연이 커지고, Claude를 부르지 않는 안내에는 쓸 수 없다.
* **코드 글자 수만(설계 v1.12)**: 결과가 늘 같다. 하지만 사용자가 언어를 직접 요청한 문장과 고유명사가 긴 문장을 틀린다.
* **Claude가 문장의 뜻으로 판단, 코드 판별은 "모호할 때" 기본값**: 언어 요청은 맞히지만, 일본어 화면에서 일본 시술명이 섞인 한국어 문장을 일본어로 답하는 일이 잦다(4절).
* **응답 칸 `reply_lang` 추가(팀원 제안)**: Claude가 고른 언어를 칸에 적게 한다. 칸과 실제로 쓴 답의 언어가 다를 수 있고, 응답 스키마·가짜 LLM·녹화본도 바꿔야 한다.
* **코드가 정하고 언어 요청만 Claude가 따름, 서버 문구는 실제 답 글자로 확인(채택)**

## 3. 결정 사항 (Decision Outcome)

* **선택한 옵션:** 코드가 정하고 언어 요청만 Claude가 따른다. 서버 문구는 실제 답 글자로 확인한다.
  * **1차 판별(코드, `api/agent/lang.py`):**
    * 메시지의 한글 수와 일본어 글자 수(히라가나 + 가타카나 + 한자)를 세어 많은 쪽으로 정한다. 가운뎃점·장음 같은 문장부호(・ー ｰ ㆍ)는 세지 않는다.
    * 한글이 있고 일본어 글자가 가타카나뿐이면 한국어로 본다("リジュラン 얼마?").
    * 같거나 둘 다 0이면 직전 턴 응답 언어, 첫 턴이면 화면 언어를 쓴다. 직전 턴 응답 언어는 Claude가 실제로 답한 턴의 언어다(`answered_lang`). 실패한 턴(시세표 안내)은 바꾸지 않는다.
    * 이 값은 언어 안내, 턴 상한·하루 한도·키 없음·오류 안내, 데모 녹화본 찾기에 쓴다.
    * `busy` 안내는 대화 잠금 전이라 대화 기록을 읽지 않는다. 이번 메시지 글자만 보고, 못 정하면 화면 언어를 쓴다.
  * **언어 안내(그 턴 사용자 메시지 끝):**
    * "이번 턴은 {1차 판별 언어}로 답하라. 다른 언어의 이름·단어가 섞여도 유지한다. 사용자가 다른 언어로 답해 달라고 직접 요청할 때만 그 언어로."
    * 예시 두 개를 붙이되, 측정 입력과 다른 문장으로 둔다.
    * 시스템 프롬프트 끝 줄은 "모든 칸을 그 한 언어로 쓴다"로 바꾼다. 턴마다 같아서 캐시 앞부분은 바뀌지 않는다.
  * **확인(코드, finalize):**
    * Claude가 쓴 답변·조건 요약·질문과 선택지·다음 질문 제안의 글자를 세어 이번 응답 언어로 정한다. 정할 수 없으면 1차 판별을 쓴다.
    * 이 언어로 면책·금액 주의 문구를 붙이고, 응답 `ChatResponse.lang`과 `answered_lang`에 남긴다.
* **선택 이유:**
  * 흔한 입력은 일본어 화면에서 한국어 문장에 일본 시술명이 섞인 경우다. 이런 입력은 코드가 정할 때 늘 맞고 결과도 같다. Claude에게 판단을 맡기면 일본어 쪽으로 기운다(4절).
  * Claude는 "한국어로 말해줘" 같은 언어 요청을 잘 알아듣는다. 그래서 이 경우만 맡긴다.
  * 서버 문구는 사용자가 실제로 보는 답과 같은 언어여야 한다. 답 글자로 확인하면 Claude가 요청에 따라 언어를 바꿔도 어긋나지 않는다. 추가 호출도 없다.

## 4. 측정 (실제 Claude, Haiku 5.5)

`scripts/eval_reply_lang.py`로 혼합 입력을 3회씩 돌렸다. 맞힘은 응답의 `lang`(실제 답 글자를 센 결과)을 기대 언어와 비교한 것이다.

* `tuning` 세트(16개): 언어 안내를 고칠 때 본 입력이다. 판단이 갈릴 수 있는 "강남 リジュラン"은 맞힘에서 뺐다.
* `holdout` 세트(15개): 안내를 고칠 때 보지 않은 입력이다.

| 방식 | tuning 맞힘 | holdout 맞힘 |
|---|---|---|
| 코드 지정만(`--mode code`) | 11/15 (1회) | 12/15 (1차 판별로 계산) |
| Claude가 뜻으로 판단(보강한 안내) | 45/45 | **36/45** |
| **코드 지정 + 언어 요청만 따름(채택)** | **41/45** | **43/45** |

* **Claude 판단 방식은 과적합이었다.** tuning에서 틀린 입력을 보고 안내를 고쳐 45/45가 됐다. 그러나 holdout에서는 일본어 화면의 "일본 시술명 + 한국어 문장"을 9회 일본어로 답했다. 예: "ピコトーニング 몇 번 받아야 효과 있어요?" 0/3, "ダーマペン 4 홍대에서 얼마?" 1/3. 시스템 프롬프트가 일본인 사용자 상담원으로 시작하고 화면도 일본어라 일본어 쪽으로 기운 것으로 본다(추정).
* **채택안은 이런 입력을 두 세트 모두 3회 다 맞혔다.**
* **채택안이 틀린 것:**
  * "밴스의원 홍대점 どう?" 0/3: 한국 병원 이름이 길어 1차 판별이 한국어다. 언어 요청이 아니라서 바꾸지 않는다. 알려진 한계다.
  * "일본어로 알려줘. 리쥬란 가격" 2/3, "韓国語で教えてもらえますか？ 리쥬란" 1/3: 언어 요청을 가끔 놓친다.
* **칸 사이 언어 섞임:** 채택안 1회("500?" 다음 턴).
* **측정 한계:** 입력이 31개라 작다. 모델은 Haiku 5.5만 썼다. 시나리오 평가(`eval_scenarios.py`)는 언어 안내를 바꾼 뒤 다시 돌리지 않았다.

## 5. 결과 및 영향 (Consequences)

* **장점:**
  * 흔한 입력(일본 시술명이 섞인 한국어 문장)은 코드가 정해 결과가 늘 같고, 단위 테스트로 막는다.
  * 언어 요청은 대부분 따른다(holdout 언어 요청 3개 중 7/9회).
  * 면책·금액 주의 문구는 항상 화면에 나간 답과 같은 언어다.
* **단점 및 위험:**
  * 한국 병원 이름이 긴 일본어 문장("밴스의원 홍대점 どう?")은 한국어로 답한다.
  * 언어 요청을 가끔 놓친다. 이때는 1차 판별 언어로 답한다.
  * Claude를 부르지 않는 안내는 1차 판별을 쓴다. 같은 메시지라도 정상 답과 오류 안내의 언어가 다를 수 있다. 예: "한국어로 말해줘. リジュランの価格"는 정상 답이 한국어, 오류 안내는 일본어다.
  * 화면 언어 전환 버튼은 다음 답의 언어를 바꾸지 않는다. 답은 사용자가 쓴 언어를 따른다.
  * web이 만드는 글자는 화면 언어다("이어서 물어보기" 같은 제목, 시세표 보기 상자, 카드 예약 버튼이 보내는 문장). 카드 버튼 문장은 다음 턴 입력이 되므로, 화면 언어로 보내면 대화 언어가 바뀐다. 응답의 `lang`으로 맞추는 일은 web 담당과 이어서 한다.
  * 데모 대본은 이 변경 뒤에 녹화한다. `record_demo.py`는 1차 판별이나 답 언어가 `--lang`과 다르면 녹화하지 않는다.
