# [ADR-0010] 환율은 배포된 web의 naver-fx.json을 읽고, 실패하면 마지막 값과 스냅샷 값을 쓴다

* **상태 (Status):** 채택됨(Accepted)
* **날짜 (Date):** 2026-11-27
* **관련 (Related):** T2 #5, ADR 0001, ADR 0007, 설계 문서 9장

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:**
  * web은 빌드할 때(`prebuild`의 `scripts/fetch-naver-fx.mjs`) 네이버에서 환율을 한 번 받아 `naver-fx.json`으로 배포한다.
  * 화면은 열릴 때 같은 서버의 `/naver-fx.json`을 읽는다. 실행 중에 네이버를 다시 부르지 않고, 정해진 시각에 다시 빌드하는 설정도 없다.
  * 그래서 web의 환율은 마지막 배포 때 값이다.
* **문제:**
  * 에이전트는 web 데이터를 복사한 스냅샷(ADR 0007)의 환율을 썼다. 이 값은 복사 스크립트를 실행한 날의 값이다.
  * web을 빌드한 날과 복사한 날이 다르면, 같은 병원의 엔화 금액이 화면과 에이전트에서 다르다. 예를 들어 148,500원은 843.68원(11/25)에서 ¥17,601, 844.10원(11/26)에서 ¥17,593이다.
  * 설계 문서 9장의 "환율은 web과 같은 값"과 맞지 않는다.
* **목표:** 에이전트의 엔화 금액이 web 화면과 같고, web을 읽지 못해도 에이전트가 답할 수 있다.

## 2. 고려한 옵션들 (Considered Options)

### 1. 배포된 web의 naver-fx.json을 읽고, 실패하면 마지막 값과 스냅샷 값을 쓴다

에이전트가 web 화면이 읽는 바로 그 파일(`WEB_FX_URL`)을 읽는다.

**Pros**
* web 화면과 같은 환율이 된다. web이 다시 배포되면 에이전트도 따라간다.
* 네이버를 직접 부르지 않으므로 외부 서비스 호출이 늘지 않는다.

**Cons**
* 에이전트가 web 주소를 알아야 한다(환경변수 하나).
* web을 읽지 못하는 동안에는 web과 다를 수 있다.

### 2. 스냅샷 환율만 쓰고 설계 문서 문구를 고친다

**Pros**
* 코드 변경이 없다.

**Cons**
* 복사 스크립트를 다시 돌리기 전까지 web과 계속 다르다.

### 3. 에이전트가 네이버에서 직접 받는다

**Pros**
* web 없이도 최신 환율을 쓴다.

**Cons**
* web은 배포 때 값에 고정돼 있어서, 에이전트만 더 최신 값이 되어 오히려 web과 달라진다.
* 외부 서비스 호출과 차단 위험이 늘어난다.

## 3. 결정 사항 (Decision Outcome)

* **배포된 web의 `naver-fx.json`을 읽고, 실패하면 마지막으로 읽은 값, 그것도 없으면 스냅샷 값을 쓴다.**
* **스냅샷만 쓰는 방식과 네이버 직접 조회는 채택하지 않는다.**

동작(`api/domain/fx.py`의 `FxProvider`)

| 항목 | 값 |
| --- | --- |
| 읽는 곳 | 환경변수 `WEB_FX_URL`(예: `https://<web 주소>/naver-fx.json`). 비어 있으면 스냅샷 환율만 쓴다(로컬, CI, 테스트) |
| 읽는 순서 | web 파일 → 마지막으로 읽은 값 → 스냅샷 값 |
| 다시 읽는 간격 | 10분. web 파일은 web을 배포할 때만 바뀐다 |
| 시간 제한 | 2초 |
| 실패로 보는 경우 | 시간 초과, HTTP 오류, JSON·형식 오류, 100엔당 600~1500원 범위 밖(web `App.tsx`와 같은 범위) |
| 실패 뒤 재시도 | 다음 10분이 지난 뒤. web이 내려가 있을 때 요청마다 2초씩 기다리지 않게 한다 |
| 마지막 값 보관 | API 서버 메모리. 재시작하면 지워지고, 다시 읽을 때까지 스냅샷 값을 쓴다 |

* 카드의 `krwPer100Jpy`와 `fxDateLabel`에는 실제로 쓴 환율과 그 기준일이 들어간다. LLM 요약에도 같은 값이 들어간다.
* 읽기 실패는 경고 로그로 남긴다.

**이유**
* web 화면과 같은 숫자를 보여 주는 것이 목표이고, 그러려면 web이 쓰는 파일을 그대로 읽는 것이 가장 확실하다.
* 대체 순서를 두면 web이 잠시 내려가도 에이전트는 계속 답한다.

**후속 작업**
* 배포 환경에 `WEB_FX_URL`을 설정한다(박준석 님). 서비스 사이 내부 주소를 쓸지 공개 주소를 쓸지는 배포 구조에 맞춰 정한다
* 재시작 뒤에도 마지막 값을 유지해야 하면, 메모리 DB를 정할 때(설계 15장) 함께 저장한다
